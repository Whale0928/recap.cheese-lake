# ui

React와 Vite로 구성한 프론트엔드다. 디자인 시스템은 기존 결정대로
**shadcn/ui 토큰 규격**을 따른다.

기존 정적 갤러리의 토큰과 컴포넌트 CSS를 React에서도 그대로 사용한다.

```
ui/
├── src/                  React 애플리케이션
├── styles/
│   ├── tokens.css       색·모서리·서체 토큰 (shadcn/ui 변수 이름 그대로, oklch)
│   └── components.css   컴포넌트 층 (shadcn/ui 어휘 + recap 전용 블록)
├── gallery.html         살아 있는 스타일 참조. 토큰과 컴포넌트 전부를 한 화면에
├── index.html           메인 페이지 진입점
└── recap/               리캡 페이지 진입점
```

## 보는 방법

```
task ui:dev                   # http://localhost:5273
task api:dev                  # UI를 빌드하고 http://localhost:8180에서 함께 제공
```

- `/` — 메인 페이지
- `/gallery.html` — 스타일 갤러리. 우상단 「테마 전환」으로 라이트·다크를 오간다
- `/recap/` — 로그인 후 전체·월별 활동 데이터를 조회한다. 요일·시간대별 활동은 요일 선택과 시간대별 채팅 수 선 그래프로 표시한다. 일별 활동 표는 노출하지 않는다.
- `/me/` — 치지직 프로필과 전체 기간 활동 요약, 최근 1년 활동 달력을 표시한다.

## 규칙

화면에 불필요한 문장형 설명을 넣지 않는다. 짧은 항목명·상태·동작 이름으로 표현한다. 프로필에는 이미지·닉네임·정보 확인 시각만 표시하고, 채널 ID·팔로워 수·인증 마크·이미지 등록 여부는 노출하지 않는다.

**토큰 밖의 색을 쓰지 않는다.** 새 색이 필요하면 `tokens.css` 에 토큰을 먼저 만든다.
컴포넌트 CSS 에 리터럴 색이 들어가는 순간 다크 모드가 조용히 깨진다.

**테마는 세 상태다.** 라이트, 시스템 다크, 이용자가 직접 고른 것.
색을 `@media` 안에서만 정의하면 첫 번째 상태에서 비어 버리므로
`:root` 에 전부 정의하고 나머지는 덮어쓰기만 한다.

**Tailwind 는 쓰지 않는다.** 기존 토큰과 컴포넌트 CSS를 React가 직접 소비한다.

## UI 미리보기 배포

`Dockerfile`은 UI만 빌드하고 nginx의 8080 포트로 제공한다.
Node와 nginx 베이스 이미지는 Lab Admin UI의 기존 구성을 따른다.
NestJS API와 OAuth는 포함하지 않는다. 이 이미지에서 「내 리캡 보기」는
로그인 없이 빈 `/recap/` 페이지를 연다.
`/api/`는 404를 반환하며 로그인 상태를 만들지 않는다.

```sh
docker build -t docker-registry.dead-whale.org/recap-ui:0.0.2 ui
docker run --rm -p 18180:8080 docker-registry.dead-whale.org/recap-ui:0.0.2
```

배포 선언은 `deploy.cheese-lake` 저장소의 `base/recap-ui.yaml`과
`base/recap-route.yaml`에 있다. 공개 주소는 `https://recap.cheese-lake.com`이다.
이미지 push와 deploy 저장소의 main 반영 후에만 실제 배포가 진행된다.

## API 연결 배포 이미지

`docker build --build-arg RECAP_API_PROXY=true -t recap-ui:local ui`로 API 프록시 템플릿을 포함한다.
`RECAP_API_UPSTREAM=http://recap-api:8180`을 주입하면 `/auth/`·`/api/`를 내부 API로 전달한다.
기본 빌드는 계속 nginx 전용 미리보기다. API 프록시 빌드에서는 접속 IP와 OAuth code가
nginx 요청 로그에 남지 않도록 access log를 끄고 인증 경로의 오류 로그도 제외한다.

## 사용자 노출 문구

화면·상태·오류·접근성 문구에 Lab 등 내부 서비스명, 호스트명, 저장소명이나 연동 구조를 노출하지 않는다. 데이터 제공자를 별도 공간처럼 표시하지 않으며, 사용자에게는 `활동 정보`와 `활동 정보 확인`으로 표현한다. 내부 API 오류 원문도 화면에 그대로 표시하지 않는다.

## 조회·재시도 제한

새로고침, 페이지 재진입, 조회 버튼 연타로 같은 요청을 무제한 실행하지 않는다. 사용자와 조회 조건을 기준으로 유효 시간 동안 결과를 재사용하고, 진행 중인 동일 요청은 합친다.

실패한 요청의 재시도에는 지수 백오프와 지터를 적용하고, 최대 대기 시간과 자동 재시도 횟수를 제한한다. 서버가 `Retry-After`를 제공하면 해당 시각 전에는 재요청하지 않는다. 수동 재시도에도 대기 시간을 적용한다.

캐시 만료 시각과 다음 요청 가능 시각은 새로고침이나 페이지 이동으로 초기화되지 않도록 유지한다. 사용자와 조회 조건별로 구분하고, 로그아웃하거나 계정이 바뀌면 이전 사용자의 데이터는 재사용하지 않는다. 인증정보는 브라우저 저장소에 보관하지 않는다.

기능별로 캐시 유효 시간, 최소 조회 간격, 백오프 상한과 재시도 횟수를 명시하고, 새로고침·연속 클릭·페이지 재진입·실패 반복·로그아웃에서 제한이 유지되는지 검증한다. UI 제한만으로 서버를 보호한다고 가정하지 않으며, 서버에서도 요청 제한을 적용한다.

## 내 활동 달력

내 정보의 요약은 전체 수집 기간, 활동 달력은 오늘을 포함한 최근 365일의 한국 시간 기준 일별 채팅 수를 표시한다. 확인된 채팅이 없는 날은 빈 색으로 표시하고, 조회 실패를 빈 활동으로 바꾸지 않는다. 날짜를 누르거나 방향키로 이동하면 해당 날짜의 활동 강도를 잔디 색과 동일한 단계의 이모지로 표시한다. 하단에는 날짜·채팅 건수 대신 이모지만 노출하며, 접근성 이름으로 날짜와 활동 강도를 제공한다. 좁은 화면에서는 달력 영역만 가로로 스크롤한다.

시간대 차트는 전체 요일 또는 선택한 요일의 채팅 수를 0~23시별로 합산한다. 일별 잔디는 내 정보에서 최근 365일만 표시한다. 차트의 요일 선택은 추가 API 요청 없이 처리한다. 시간 축은 넓은 화면에서 1시간 간격으로 표시하고, 좁은 화면에서는 겹치지 않도록 2~3시간 간격으로 조절한다. 시간대 선택 표시와 슬라이더는 제공하지 않는다.

요일·시간대 차트의 기간 선택은 요일 버튼 앞에 배치하고, 상단의 전체·월별 선택과 같은 상태를 공유한다. 기간이나 월을 바꿔도 선택한 요일은 유지한다. 좁은 화면에서는 기간 선택과 요일 선택을 두 줄로 배치한다.

조회 조건을 바꿀 때 기존 본문을 제거하지 않고 갱신 상태만 표시한다. 갱신 중에는 마지막 성공 데이터와 실제 조회 기간을 유지하고, 실패 시에도 기존 화면을 유지한다. 인증 실패 시에는 즉시 데이터를 숨긴다. 차트 필터의 화면상 위치를 갱신 전후에 유지하며, 취소된 요청의 늦은 응답은 반영하지 않는다. 초기 로그인 상태 확인만으로 본문을 다시 마운트하지 않는다.

사용자에게 노출하는 데이터 문구는 `확인된 채팅`으로 통일한다.
