# ui

React와 Vite로 구성한 프론트엔드다. 디자인 시스템은 기존 결정대로
**shadcn/ui 토큰 규격**을 따른다.

기존 정적 갤러리의 토큰과 컴포넌트 CSS를 React에서도 그대로 사용한다.

```
ui/
├── src/                  React 애플리케이션
├── styles/
│   ├── tokens.css       색·모서리·서체 토큰 (shadcn/ui 변수 이름 그대로, oklch)
│   └── components.css   컴포넌트 층 (shadcn/ui 어휘 + recap 전용 블록)
├── gallery.html         살아 있는 스타일 참조. 토큰과 컴포넌트 전부를 한 화면에
├── index.html           메인 페이지 진입점
└── recap/               리캡 페이지 진입점
```

## 보는 방법

`pnpm build`는 React 홈페이지를 정적 HTML로 미리 렌더링한다. 브라우저에서는
기존 React 진입점이 테마·세션·버튼 동작을 초기화한다. 개인 화면은 미리
렌더링하지 않으며 `noindex`를 유지한다. `pnpm test:seo`로 빌드 결과의 공개
본문, 대표 URL, sitemap과 개인 화면의 색인 차단을 확인한다.

검색 등록은 배포 후 계정 소유자가 별도로 진행한다.

- Google Search Console에서 `recap.cheese-lake.com`의 소유권을 확인하고
  `https://recap.cheese-lake.com/sitemap.xml`을 제출한다. URL 검사에서
  홈페이지의 렌더링 결과를 확인하고 색인 생성을 요청한다.
- 네이버 서치어드바이저에서 같은 사이트의 소유권을 확인하고 사이트맵을
  제출한다. 홈페이지 수집을 요청하고 수집·색인 상태를 확인한다.
- DNS 또는 HTML 확인 파일처럼 도구가 발급한 실제 소유권 확인 값을 사용한다.
  이 저장소에는 계정별 확인 값을 임의로 넣지 않는다.

공식 안내: [Google sitemap 제출](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap),
[네이버 웹마스터 가이드](https://searchadvisor.naver.com/guide).

```
task ui:dev                   # http://localhost:5273
task api:dev                  # UI를 빌드하고 http://localhost:8180에서 함께 제공
```

- `/` — 메인 페이지
- `/gallery.html` — 스타일 갤러리. 우상단 「테마 전환」으로 라이트·다크를 오간다
- `/recap/` — 로그인 후 전체·월별 활동 데이터를 조회한다. 방송별 활동은 도넛을 기본으로 카드·목록·트리맵 전환을 제공한다. 차트는 상위 15개 방송 외에 기타로 묶고, 카드·목록은 상위 15개 외 방송을 접어 두며 펼칠 수 있게 한다. 요일·시간대별 활동은 요일 선택과 시간대별 채팅 수 선 그래프로 표시한다. 일별 활동 표는 노출하지 않는다.
- `/me/` — 치지직 프로필과 전체 기간 활동 요약, 최근 1년 활동 달력을 표시한다.
- `/recap/channel/?channel=방송ID` — ‘이 채널에서의 내 기록’ 화면. C 타입 레이아웃에 실제 채널별 요약, 전체 기간 월별 기록과 최근 1년 잔디를 연결한다. 공유 버튼은 표시만 하며 API를 호출하지 않는다.

## 규칙

방송별 활동의 프로필 이미지·채널명과 본진 카드는 채널 기록 페이지로 이동한다. 도넛·트리맵 범례에서는 이미지·이름 링크와 비율 선택 버튼을 나눠 중첩 버튼을 만들지 않는다. 비율 버튼과 차트 조각은 선택만 바꾸며, 기타 목록의 이미지·이름도 채널 기록 페이지로 이동한다. 시안 확인용으로 공개 채널 메타데이터 한 건만 sessionStorage로 전달하고 사용자 활동이나 인증정보는 저장하지 않는다. 실제 기록 화면은 서버가 반환한 채널 메타데이터를 사용하며 사용자 ID를 입력받지 않는다. `GET /api/me/channels/:broadcastId/record`를 호출하고 사용자 ID는 서버의 로그인 세션으로만 결정한다.

내 리캡 상단의 본진 카드는 선택한 조회 기간의 채팅 비율이 50% 이상인 채널만 표시한다. 반올림 전 응답 비율로 판별하고, 정확히 50%인 채널이 둘이면 모두 표시한다. 기존 방송별 활동 응답을 재사용하며 이미지·채널명·채팅 비율만 노출한다. 이미지가 없거나 로딩에 실패하면 채널명 첫 글자로 대체한다.

화면에 불필요한 문장형 설명을 넣지 않는다. 짧은 항목명·상태·동작 이름으로 표현한다. 프로필에는 이미지·닉네임·정보 확인 시각만 표시하고, 채널 ID·팔로워 수·인증 마크·이미지 등록 여부는 노출하지 않는다.

**토큰 밖의 색을 쓰지 않는다.** 새 색이 필요하면 `tokens.css` 에 토큰을 먼저 만든다.
컴포넌트 CSS 에 리터럴 색이 들어가는 순간 다크 모드가 조용히 깨진다.

**테마는 세 상태다.** 라이트, 시스템 다크, 이용자가 직접 고른 것.
색을 `@media` 안에서만 정의하면 첫 번째 상태에서 비어 버리므로
`:root` 에 전부 정의하고 나머지는 덮어쓰기만 한다.

**Tailwind 는 쓰지 않는다.** 기존 토큰과 컴포넌트 CSS를 React가 직접 소비한다.

## UI 미리보기 배포

`Dockerfile`은 UI만 빌드하고 nginx의 8080 포트로 제공한다.
Node와 nginx 베이스 이미지는 Lab Admin UI의 기존 구성을 따른다.
NestJS API와 OAuth는 포함하지 않는다. 이 이미지에서 「내 리캡 보기」는
로그인 없이 빈 `/recap/` 페이지를 연다.
`/api/`는 404를 반환하며 로그인 상태를 만들지 않는다.

```sh
docker build -t docker-registry.dead-whale.org/recap-ui:0.0.2 ui
docker run --rm -p 18180:8080 docker-registry.dead-whale.org/recap-ui:0.0.2
```

배포 선언은 `deploy.cheese-lake` 저장소의 `base/recap-ui.yaml`과
`base/recap-route.yaml`에 있다. 공개 주소는 `https://recap.cheese-lake.com`이다.
이미지 push와 deploy 저장소의 main 반영 후에만 실제 배포가 진행된다.

## API 연결 배포 이미지

`docker build --build-arg RECAP_API_PROXY=true -t recap-ui:local ui`로 API 프록시 템플릿을 포함한다.
`RECAP_API_UPSTREAM=http://recap-api:8180`을 주입하면 `/auth/`·`/api/`를 내부 API로 전달한다.
기본 빌드는 계속 nginx 전용 미리보기다. API 프록시 빌드에서는 접속 IP와 OAuth code가
nginx 요청 로그에 남지 않도록 access log를 끄고 인증 경로의 오류 로그도 제외한다.

## 사용자 노출 문구

화면·상태·오류·접근성 문구에 Lab 등 내부 서비스명, 호스트명, 저장소명이나 연동 구조를 노출하지 않는다. 데이터 제공자를 별도 공간처럼 표시하지 않으며, 사용자에게는 `활동 정보`와 `활동 정보 확인`으로 표현한다. 내부 API 오류 원문도 화면에 그대로 표시하지 않는다.

## 조회·재시도 제한

### 브라우저 연산 우선

방송별 활동은 카드·목록·도넛·트리맵 보기를 제공한다. 도넛과 트리맵은 채팅 수가 양수인 상위 15개 채널을 개별 표시하고 나머지는 기타로 합산한다. 마우스 호버·키보드 포커스로 상세를 확인하고 클릭·Enter·Space·터치로 선택을 유지한다. 기타 상세에서는 묶인 모든 채널의 이름·이미지·채팅 수·비율을 스크롤 목록으로 보여준다. Escape는 선택을 초기화한다. 보기와 상세 선택, 차트 좌표 계산은 기존 응답을 재사용하며 API를 호출하지 않는다.

도넛 중앙과 트리맵 내부에 채널 프로필·이름·채팅 수·비율·활동일을 표시하며 하단 상세 영역은 두지 않는다. 작은 트리맵 조각의 상세는 차트 안에 겹쳐 표시한다. 범례는 프로필 이미지와 차트 블록과 같은 색면을 사용한다. 차트와 범례는 미리 정의한 차트 색상 토큰을 사용하며, 프로필에서 색상을 추출하거나 추론하지 않는다. 기타 목록은 데스크톱에서 차트 위에, 모바일에서 화면 하단 패널로 표시하며 아래 본문을 밀지 않는다.

이미 내려받은 데이터의 정렬·필터·접기·보기 방식 전환·차트 좌표 계산은 브라우저에서 처리한다. 화면 표현만 바뀔 때 API를 다시 호출하지 않는다. 방송별 활동의 카드·목록 전환과 상위 15개 외 방송 접기도 같은 응답을 재사용한다. 새로운 서버 계산이나 조회를 추가하기 전에 브라우저에서 처리할 수 있는지 먼저 검토한다.

계산량이 커져 스크롤·입력·터치를 방해하면 메모이제이션, 화면에 보이는 항목만 렌더링하는 방식, Web Worker를 작업량에 맞게 적용한다. 모바일에서도 조작 응답성과 메모리 사용을 확인한다. 인증·인가와 사용자 식별은 서버에서 처리하고, 전체 원본 채팅을 브라우저로 내려받아 집계하지 않는다. 브라우저에는 해당 화면에 필요한 집계 결과만 전달한다.

### 요청 간격

새로고침, 페이지 재진입, 조회 버튼 연타로 같은 요청을 무제한 실행하지 않는다. 사용자와 조회 조건을 기준으로 유효 시간 동안 결과를 재사용하고, 진행 중인 동일 요청은 합친다.

실패한 요청의 재시도에는 지수 백오프와 지터를 적용하고, 최대 대기 시간과 자동 재시도 횟수를 제한한다. 서버가 `Retry-After`를 제공하면 해당 시각 전에는 재요청하지 않는다. 수동 재시도에도 대기 시간을 적용한다.

캐시 만료 시각과 다음 요청 가능 시각은 새로고침이나 페이지 이동으로 초기화되지 않도록 유지한다. 사용자와 조회 조건별로 구분하고, 로그아웃하거나 계정이 바뀌면 이전 사용자의 데이터는 재사용하지 않는다. 인증정보는 브라우저 저장소에 보관하지 않는다.

기능별로 캐시 유효 시간, 최소 조회 간격, 백오프 상한과 재시도 횟수를 명시하고, 새로고침·연속 클릭·페이지 재진입·실패 반복·로그아웃에서 제한이 유지되는지 검증한다. UI 제한만으로 서버를 보호한다고 가정하지 않으며, 서버에서도 요청 제한을 적용한다.

## 내 활동 달력

내 정보의 요약은 전체 수집 기간, 활동 달력은 오늘을 포함한 최근 365일의 한국 시간 기준 일별 채팅 수를 표시한다. 확인된 채팅이 없는 날은 빈 색으로 표시하고, 조회 실패를 빈 활동으로 바꾸지 않는다. 날짜를 누르거나 방향키로 이동하면 해당 날짜의 활동 강도를 잔디 색과 동일한 단계의 이모지로 표시한다. 하단에는 날짜·채팅 건수 대신 이모지만 노출하며, 접근성 이름으로 날짜와 활동 강도를 제공한다. 좁은 화면에서는 달력 영역만 가로로 스크롤한다.

시간대 차트는 전체 요일 또는 선택한 요일의 채팅 수를 0~23시별로 합산한다. 일별 잔디는 내 정보에서 최근 365일만 표시한다. 차트의 요일 선택은 추가 API 요청 없이 처리한다. 시간 축은 넓은 화면에서 1시간 간격으로 표시하고, 좁은 화면에서는 겹치지 않도록 2~3시간 간격으로 조절한다. 시간대 선택 표시와 슬라이더는 제공하지 않는다.

전체·월별 조회 기간은 내 리캡 제목 아래 한 곳에서만 선택하며 본진 카드·활동 요약·방송별 활동·시간대 차트에 공통으로 적용한다. 차트에는 요일 선택만 표시하며 요일 변경은 차트에만 적용한다. 기간이나 월을 바꿔도 선택한 요일은 유지한다.

조회 조건을 바꿀 때 기존 본문을 제거하지 않고 갱신 상태만 표시한다. 갱신 중에는 마지막 성공 데이터와 실제 조회 기간을 유지하고, 실패 시에도 기존 화면을 유지한다. 인증 실패 시에는 즉시 데이터를 숨긴다. 차트 필터의 화면상 위치를 갱신 전후에 유지하며, 취소된 요청의 늦은 응답은 반영하지 않는다. 초기 로그인 상태 확인만으로 본문을 다시 마운트하지 않는다.

사용자에게 노출하는 데이터 문구는 `확인된 채팅`으로 통일한다.

로컬 개발 로그인이 활성화되고 로그아웃 상태일 때만, 공통 헤더의 내 리캡 보기 옆에 채널 ID로 로그인 링크를 표시한다. 노출 여부는 `/api/session`의 `localLoginAvailable` 값으로 판정한다.

## 공통 홍보 패널

서비스 페이지의 홍보 패널은 `App.tsx`의 공통 레이아웃에서 한 번만 렌더링한다. 홈·내 정보·내 리캡·채널 기록·개인정보 처리방침·이용약관에 같은 규칙을 적용하며, 로그인·로그아웃·조회 실패 상태에서도 위치를 유지한다. 독립적인 디자인 시안·스타일 갤러리와 로컬 개발 로그인 도구는 서비스 레이아웃에 포함하지 않는다.

홍보 내용·이미지·외부 링크·안내 일정과 좌우 슬롯 배정·레이아웃은 `src/promotion.config.ts`에서 관리한다. 슬롯을 `null`로 두면 해당 패널을 표시하지 않는다. 일정은 안내 문구이며 자동 노출 예약이나 만료 처리를 뜻하지 않는다. 화면별로 홍보 HTML이나 CSS를 복사하지 않는다.

크기와 배치는 `src/sideBanners.css`의 공통 변수로 관리한다. 최대 본문 폭 72rem, 패널 폭 16rem, 본문과 간격 8rem, 바깥 여백 2rem을 기준으로 양쪽을 확보할 수 있는 124rem(기본 1,984px) 이상에서만 표시한다. 그보다 좁으면 두 패널 모두 숨기며 본문 자리를 차지하지 않는다. 너비 기준을 바꿀 때 이 합계를 함께 검토한다.

패널의 바깥 크기는 양쪽 모두 폭 16rem·높이 52.5rem으로 고정하고 화면이 낮을 때만 최대 높이를 제한한다. 내부 콘텐츠는 패널 높이를 채워 배치하며 콘텐츠 양에 맞춰 바깥 크기를 줄이지 않는다. 좌우 모두 이미지가 상단을 채우고 본문을 중앙 정렬한 `poster`를 적용한다. 콘텐츠를 복제하지 않고 슬롯의 `layout`으로 배치를 선택한다. 높이 720px 이하에서는 이미지를, 512px 이하에서는 설명을 숨기며 남은 내용도 넘치면 패널 안에서만 스크롤한다. 헤더·본문·모달보다 앞을 가리지 않으며 기존 테마 토큰을 사용한다. 외부 링크는 새 창 안내와 `noopener noreferrer`를 공통 적용한다. 홍보물 조회를 위한 API 호출이나 사용자 추적은 추가하지 않는다.

공통 헤더의 내 정보·로그아웃은 외부 이미지·아이콘 폰트를 사용하지 않는 인라인 SVG로 표시한다. 버튼의 접근성 이름과 title을 유지하고, 클릭 영역은 최소 44px로 확보한다. 로그아웃 처리 중에는 버튼을 비활성화하고 접근성 이름에 처리 상태를 반영한다.

도넛 조각은 마우스·터치 선택 시 사각 포커스 테두리를 그리지 않는다. 선택 상태는 원호 굵기로 표시하고, 키보드 포커스는 해당 원호의 색과 굵기로 구분한다. 포커스 이동과 Enter·Space 선택 동작은 유지한다.

공통 헤더 버튼은 모두 높이 44px로 통일한다. 헤더의 내 리캡 보기만 테두리 네온을 3.8초 주기로 밝히며, 그림자 자체를 매 프레임 바꾸지 않고 별도 레이어의 불투명도만 조절한다. `prefers-reduced-motion: reduce`와 로그인 확인 중 비활성 상태에서는 애니메이션을 멈춘다. 본문의 리캡 버튼은 기존 스타일을 유지한다.
