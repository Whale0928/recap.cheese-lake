# 0005 브라우저에서 그리는 채널 기록 카드

상태: Accepted (2026.10.28)

## 배경

채널 기록 카드 PNG는 서버가 satori와 resvg(WASM)로 그렸다. 치지직 프로필 CDN이 CORS 헤더를 주지 않아 브라우저 canvas가 사진을 꺼낼 수 없고, Pretendard 동적 서브셋을 canvas에 담기 어렵다는 이유였다.

운영에서 저장 버튼을 누르면 체감이 느렸다. 운영 recap-api 컨테이너에서 같은 렌더 함수를 실행하면 첫 요청 약 2초, 이후 요청 약 0.5초가 걸렸고, 그중 대부분이 resvg 래스터화였다. 파드의 CPU limit이 500m이라 cgroup 쓰로틀링이 걸리고, 렌더가 이벤트 루프를 막는 동기 작업이라 카드 요청이 겹치면 리캡 조회와 healthz까지 함께 늦어진다. 카드에 들어갈 수치는 이미 화면에 있다.

## 결정

카드는 브라우저가 canvas로 그리고 PNG로 인코딩한다. 서버는 카드를 그리지 않는다.

- 프로필 사진은 `GET /api/me/channels/:broadcastId/avatar`가 바이트만 중계한다. 사진 주소는 클라이언트에서 받지 않고 Lab 관계 조회 캐시의 `channelImageUrl`을 쓴다. 허용 호스트·크기·형식·시간 제한은 이전 서버 렌더와 같다.
- 글꼴은 홈과 같은 Pretendard 동적 서브셋을 쓴다. 홈을 뺀 페이지들은 그동안 이 서체 CSS를 싣지 않아 기기 서체로 그려졌으므로 모든 페이지의 `index.html`에 같은 링크를 넣고, 카드에 들어갈 글자를 기준으로 `document.fonts.load`로 미리 받은 뒤 그린다. 글꼴이 같으므로 기기마다 글자 모양이 달라지지 않는다.
- 서비스 아이콘은 UI 자산의 `favicon.svg`를 그대로 쓴다.
- satori, resvg 의존성과 API 이미지의 서체 자산을 제거한다.

## 결과

- 저장 비용이 사용자 기기로 옮겨가 동시 요청이 서버 응답성에 영향을 주지 않는다.
- 사진 중계는 CPU를 쓰지 않는 I/O 작업이고 Lab 캐시를 재사용한다.
- 안티앨리어싱 같은 미세한 렌더 차이는 브라우저마다 있을 수 있다. 글꼴과 배치는 같다.
- canvas `letterSpacing`을 지원하지 않는 오래된 브라우저에서는 자간 없이 그려진다.
