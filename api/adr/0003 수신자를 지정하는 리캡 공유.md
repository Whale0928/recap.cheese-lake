# 0003. 수신자를 지정하는 리캡 공유

## Status

Accepted, 2026.10.27. 초안(2026.10.23)의 범위·기간·스냅샷·만료 설계를 버리고 "같은 화면을 그대로 보여 준다"로 단순화해 구현했다.

## Context

시청자는 "이 채널에서의 내 기록" 화면에서 해당 스트리머에게 기록을 공유할 수 있다.
스트리머는 치지직으로 로그인한 뒤 자기 리캡과 별개로 공유받은 기록을 확인한다.
공유받을 스트리머가 Recap을 이용한 적이 없어 계정 매칭 행이 없을 수 있다.

초안은 공유 범위(`channel`/`all`)·기간·스냅샷·만료 시각을 두었다. 그러나 화면에 보이는 항목이 이미
해당 채널에서의 기록으로 한정되어 있고, 스냅샷은 별도 개인정보 사본과 삭제 범위를 늘리며, 선택지가
많을수록 동의 화면이 계약서처럼 길어진다. 스트리머가 보는 것은 시청자 본인이 보는 화면과 같아야
설명이 가장 쉽다.

## Decision

공유는 "스트리머가 로그인하면 그 채널에서의 내 기록 화면을 그대로 본다"는 뜻으로 정의한다.

- `recap.recap_shares`에 소유자(시청자)·수신자(스트리머) 한 쌍의 현재 동의 하나를 저장한다.
  열은 `owner_channel_id`, `recipient_channel_id`, `consented_at` 세 개이며 두 채널 ID가 기본 키다.
- 소유자는 세션의 채널 ID다. `chzzk_accounts`를 참조하며 계정 삭제 시 공유도 삭제한다.
  수신자는 미가입 상태를 허용하므로 계정 FK를 두지 않는다.
- 범위·기간·스냅샷·만료는 없다. 수신자는 항상 소유자 본인이 보는 것과 같은 최신 기록을 본다.
  조회는 소유자 본인 조회와 같은 Lab 호출·검증·5분 캐시를 재사용한다(`channelRecord`).
- 동의 체크 없이 보낸 요청(`consent: true` 누락)과 자기 자신에게 보여 주는 요청은 400으로 거절한다.
- 수신자 조회는 인증된 수신자에게만 허용한다. 동의 행이 없으면 404, 소유자가 수집 거부·이용 제한
  상태이면 403이다. 주소만으로는 열리지 않는다. 수신자 응답에는 본인 화면 전용 프로필 재조회 일정을
  싣지 않는다.
- 해제는 행을 삭제한다. 같은 상대에게 다시 동의하면 `consented_at`만 갱신한다.
- 동의·해제·공유받은 기록 조회는 활동 로그(`share_grant`, `share_revoke`, `shared_record_view`)에 남긴다.
- 재공유나 방송 공개는 승인 범위에 포함하지 않으며, 이미 열람·캡처된 사본의 원격 회수는 보장하지 않는다.
  이 내용과 불이익 없음, 제공 항목, 보유 기간은 동의 창에서 짧은 문장으로 안내한다.

## API

| 경로 | 동작 |
|---|---|
| `GET /api/me/channels/:broadcastId/share` | 로그인한 본인이 해당 스트리머에게 보여 주는 중인지(`share` 또는 `null`) |
| `PUT /api/me/channels/:broadcastId/share` | `{ consent: true }`로 동의. 동의 시각을 돌려준다 |
| `DELETE /api/me/channels/:broadcastId/share` | 해제. `revoked`로 행이 있었는지 알려 준다 |
| `GET /api/me/shares/received` | 나(스트리머)에게 보여 주기로 한 시청자 목록(채널 ID·닉네임·동의 시각) |
| `GET /api/me/shares/received/:ownerId/record` | 그 시청자의 "이 채널에서의 내 기록" 응답에 `owner`·`consentedAt`을 더한 것 |

화면은 `/recap/channel/`의 카드 하단 버튼(동의 창, 공유 중 상태와 해제)과 `/recap/`의 "나에게 보여 준 기록" 목록,
`/recap/shared/?owner=…`의 공유 화면이다.

## Consequences

사용자는 공개 URL 대신 특정 스트리머에게 제한된 기록을 전달할 수 있다. 별도 사본이 없으므로
삭제 요청 시 정리할 것은 공유 행과 기존 캐시뿐이다. 한 소유자·수신자당 동의 하나만 두며,
항목이나 기간을 고르는 기능은 없다. 필요해지면 열을 추가하는 새 마이그레이션으로 확장한다.
