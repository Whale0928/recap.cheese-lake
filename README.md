## 무엇을 하는 서비스인가

치지직에서 채팅으로 남긴 활동을 모아, **한 해 동안 어느 방송에 얼마나 머물렀는지**를
돌려주는 리캡을 만듭니다.

- 채널별 채팅 비율과 흐름
- 날짜·시간대별 활동 리듬
- 함께 본 채널의 겹침
- 숫자를 읽히는 문장으로 풀어낸 요약
- 공유할 수 있는 요약 카드

시청만 해서는 아무것도 쌓이지 않습니다. 채팅을 남기셨을 때만 기록이 생깁니다.
이때 메시지 본문도 함께 보관하지만 **화면에 보여주지 않습니다** — 자세한 내용은
[개인정보 처리방침](legal/개인정보%20처리방침.md)에 적어두었습니다.

> **현재 상태: 설계 단계.** 아직 애플리케이션 코드가 없습니다.
> 이 저장소에는 개발 환경 설정만 있습니다.

## 원칙

개인의 활동 기록을 다루는 서비스라, 만들기 전에 지킬 것을 먼저 정했습니다.

**본인만 봅니다.** 리캡은 열람에 동의한 본인에게만 열립니다.
리캡 주소는 채널 아이디와 관계없는 무작위 식별자라 주소만으로는 열리지 않습니다.

**동의 없이는 보여주지 않습니다.** 열람 항목을 먼저 안내하고, 동의한 뒤에만 리캡을 엽니다.
동의는 언제든 철회할 수 있고, 철회하면 즉시 열람이 중단됩니다.

**로그인은 본인 확인이 전부입니다.** 치지직에 요청하는 권한은 이용자 정보 조회 하나이며,
채널 아이디와 채널명을 확인한 뒤 접근 토큰을 바로 폐기합니다. 갱신용 토큰은 받지 않습니다.

**숨기기와 지우기를 요청할 수 있습니다.** 로그인 후 화면에서 요청하며,
별도의 서류나 사유를 요구하지 않습니다.

**수집하지 않는 것** — 이메일·전화번호·주소, 성명·생년월일·성별·연령, 결제 정보.
접속 IP도 이용 기록으로 저장하지 않습니다.

**요약 생성에 외부 AI를 씁니다.** 수치는 이 서비스가 직접 계산하고, 그것을 문장으로
정리하는 부분만 위탁합니다. 이때 집계와 지표만 전송하고 **채널 아이디와 닉네임은
전송하지 않습니다.** 요약 생성에 신원 정보가 필요하지 않기 때문입니다.
전송 대상과 항목은 개인정보 처리방침에 기재합니다.

이 원칙들은 공개 전에 개인정보 처리방침과 이용약관으로 정식화됩니다.

## 개발

서브모듈이 있으므로 클론할 때 함께 받습니다.

```bash
git clone --recurse-submodules https://github.com/Whale0928/recap.cheese-lake.git
```

이미 클론했다면 다음과 같이 초기화합니다. 일부 서브모듈은 접근 권한이 필요합니다.

```bash
git submodule update --init --recursive
```

### Orca 워크트리

[Orca](https://orca.computer) 워크트리를 쓴다면 작업트리 후크에 아래 한 줄을 넣습니다.
서브모듈 초기화, 로컬 설정 복사, 워크트리별 포트 할당을 한 번에 처리합니다.

```bash
bash "$ORCA_WORKTREE_PATH/scripts/orca-setup.sh"
```

워크트리마다 포트가 달라집니다. 치지직 OAuth는 애플리케이션당 리디렉션 URL을
하나만 받고 등록값과 정확히 일치해야 하므로, 로그인 흐름을 테스트할 때는
`:8180`으로 띄우거나 8180에서 해당 워크트리로 넘겨야 합니다.

## 구조

```
recap.cheese-lake/
├── scripts/
│   └── orca-setup.sh     # 워크트리 초기화
└── module.*/             # 배포·플랫폼·설정 서브모듈
```

바이너리 하나가 서브커맨드로 역할을 가릅니다 — `recap serve`(HTTP 서버),
`recap worker`(리캡 생성).

설계 문서는 별도로 관리합니다.
